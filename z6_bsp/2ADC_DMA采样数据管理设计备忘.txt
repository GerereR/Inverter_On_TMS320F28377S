ADC、DMA与采样数据管理设计备忘
================================

文档性质
--------
本文件只记录设计思想、管理方法和未来实施顺序。
当前阶段不代表这些功能已经全部写入工程，也不要求立即修改现有代码。


一、最核心的总体思想
--------------------

1. 将“物理引脚”“ADC采样任务”“结果寄存器”“业务变量”分成四层。

   物理引脚 -> SOC任务 -> ADCRESULT寄存器 -> 语义化数据结构

2. adc.c和dma.c负责硬件差异，上层算法不直接访问ADC寄存器。

3. PLL、电流环、MPPT、保护、通信等模块只使用有明确含义的变量，例如：

   ADC_Data.instantaneous.gridVoltageV
   ADC_Data.average.pvVoltageV
   ADC_Data.rms.gridCurrentA

4. 更换ADC引脚、ADC模块、DMA通道甚至更换MCU时，尽量只修改BSP采集层。

5. 采样频率和计算频率不是一回事：

   可以每个PWM周期采样，但不必每个PWM周期都计算AVG、RMS、温度和通信数据。


二、物理通道、SOC和结果寄存器
----------------------------

1. 物理通道CHSEL决定“采谁”。

2. SOC编号决定“这是哪个采样任务”，同时决定结果进入哪个ADCRESULT寄存器。

3. TRIGSEL决定“什么时候开始采”。

4. ACQPS决定采样保持窗口长度。

5. SOC优先级和触发关系决定多个SOC请求的实际执行顺序。

示例：

   ADCB6接PV电压，ADCB3接PV电流，ADCB12接母线电压。

   可以配置为：

   ADCB6  -> SOC0 -> ADCBRESULT0 -> pvVoltage
   ADCB3  -> SOC1 -> ADCBRESULT1 -> pvCurrent
   ADCB12 -> SOC2 -> ADCBRESULT2 -> dcBusVoltage

物理通道6、3、12并不连续，但结果可以被整理到RESULT0、RESULT1、RESULT2。
这样DMA可以从RESULT0开始连续搬运，不必关心PCB上的通道编号。

如果PV电压从ADCB6改接到ADCB9，只需要改变SOC0的CHSEL：

   AdcbRegs.ADCSOC0CTL.bit.CHSEL = 9U;

SOC编号、结果地址、DMA缓冲区布局和上层MPPT算法都可以保持不变。

注意：同一个ADC模块只有一个SOC0配置寄存器。
多个物理通道不能在同一时刻都配置成SOC0，必须分别使用SOC0、SOC1、SOC2等。


三、同一ADC模块与不同ADC模块
----------------------------

1. 同一ADC模块内

   一个ADC模块通常只有一套转换核心。
   多个SOC即使被同一事件触发，也会在模块内部依次采样和转换。

   优点：
   - 可以通过SOC重新排列物理通道。
   - 可以让结果寄存器连续，便于一个DMA burst搬运。
   - 配置和管理简单。

   缺点：
   - 多个信号的真实采样时刻存在先后差异。

2. 不同ADC模块之间

   ADCA、ADCB、ADCC、ADCD可以由同一个ePWM事件同步触发，并行采样。

   适合：
   - 电网电压与电网电流。
   - 多相电流。
   - 其他对相位一致性要求高的信号。

   缺点：
   - 各ADC模块的结果寄存器地址不连续。
   - 一个普通DMA通道不能直接跨多个ADC模块做散点搬运。

3. 典型分散连接

   电网电压：ADCA0
   PV电压：  ADCB6
   PV电流：  ADCC3
   电网电流：ADCD12

   可以分别安排为：

   ADCA0  -> ADCA SOC0 -> ADCARESULT0
   ADCB6  -> ADCB SOC0 -> ADCBRESULT0
   ADCC3  -> ADCC SOC0 -> ADCCRESULT0
   ADCD12 -> ADCD SOC0 -> ADCDRESULT0

   四个模块可由同一个ePWM SOCA同步触发。


四、语义化数据结构
------------------

1. 原始ADC码结构

   typedef struct
   {
       Uint16 gridVoltage;
       Uint16 gridCurrent;
       Uint16 pvVoltage;
       Uint16 pvCurrent;
   } ADC_RawFrame;

2. 真实瞬时值结构

   typedef struct
   {
       float gridVoltageV;
       float gridCurrentA;
       float pvVoltageV;
       float pvCurrentA;
   } ADC_RealFrame;

3. 统一测量结果

   typedef struct
   {
       ADC_RealFrame instantaneous;
       ADC_RealFrame average;
       ADC_RealFrame rms;
       ADC_RealFrame rippleRms;
   } ADC_Measurement;

4. 推荐的数据流

   ADC寄存器/DMA Buffer
            |
            v
       ADC_RawFrame
            |
            | 零点、增益、极性、传感器比例换算
            v
       instantaneous
            |
            | 窗口统计
            v
       average、rms、rippleRms

5. 真实值换算的基本形式

   realValue = (rawCode - offsetCode) * gain;

   offsetCode：零点ADC码。
   gain：ADC码到V或A的比例系数，包含分压、运放和电流传感器比例。

6. volatile的使用边界

   DMA目标缓冲区、ISR与主循环共享的标志通常需要volatile。
   CPU后台计算得到的普通局部快照不应无条件全部声明为volatile。


五、快速、中速、慢速数据管理
----------------------------

快、中、慢是按“控制和更新时限”分类，不只是按信号名称分类。

1. 快速数据

   典型信号：
   - 电网电压。
   - 电感电流/电网电流。
   - 电流参考。
   - PWM更新量。

   典型处理：
   - 每个PWM周期采样。
   - ADC EOC触发CPU控制ISR。
   - ISR中立即运行PLL、电流环和PWM更新。
   - 不等待DMA块填满。

   原因：
   - 控制环最关心的是固定、短且可预测的延迟。

2. 中速数据

   典型信号或计算：
   - PV电压和PV电流的短窗口平均值。
   - 母线电压调节所需的滤波值。
   - 电网AVG、RMS、有功功率。
   - 状态监测和软件限幅。

   典型处理：
   - ADC保持较高采样率。
   - DMA累计一块数据。
   - 块完成后由Task_Measure等后台任务统一计算。

3. 慢速数据

   典型信号或计算：
   - 温度。
   - 辅助电源电压。
   - 长时间平均值。
   - 通信显示值。
   - 运行统计和故障历史。

   典型处理：
   - 降低采样触发频率，或从高速采样结果中抽取。
   - 10ms、100ms、500ms或更慢周期处理。
   - 不应占用高速控制ISR的大量时间。

4. 重要结论

   所有ADC通道可以使用同一基础采样节拍，但处理节拍应分层。
   如果ADC转换时间、功耗或DMA带宽需要进一步优化，再对慢速SOC单独降频触发。


六、DMA的基本配置思想
--------------------

1. DMA的作用

   DMA负责在外设事件到来时，将ADC结果自动搬到RAM。
   CPU不需要为每个监测采样点进入一次中断。

2. DMA的三级计数概念

   Word：一次搬运的一个数据元素。

   Burst：一次外设触发后连续搬运的一组Word。

   Transfer/Block：多个Burst组成的数据块，整个Transfer结束后产生DMA中断。

3. 两路连续ADC结果的例子

   ADCRESULT0：PV电压
   ADCRESULT1：PV电流

   每次ADCBINT2触发DMA，搬运两个16位结果：

   BURST_SIZE = 1

   因为F2837xS寄存器保存的是“数量减一”，1表示每个burst搬2个Word。

   如果累计160个burst后中断：

   TRANSFER_SIZE = 159

   160个burst共保存160组PV电压/PV电流。

4. 两路连续结果的典型地址步进

   SRC_BURST_STEP = 1
   DST_BURST_STEP = 1
   SRC_TRANSFER_STEP = -1
   DST_TRANSFER_STEP = 1

   含义：
   - burst内部从RESULT0走到RESULT1。
   - burst结束时源地址从RESULT1返回RESULT0。
   - 目标地址从本帧的第二个字段走到下一帧的第一个字段。

   注意：地址步进语义与具体MCU有关，移植到新芯片时必须重新核对DMA手册。

5. 单结果DMA流

   如果一个DMA通道每次只搬某个ADC模块的一个结果：

   BURST_SIZE = 0
   SRC地址每次保持在同一个ADCRESULT寄存器
   DST地址每个burst移动到下一个数组元素

6. 触发链

   ePWM SOCA
      -> ADC SOC转换
      -> 最后一个相关SOC产生EOC
      -> ADCINTx
      -> DMA通道执行一个burst
      -> 累计指定数量的burst
      -> DMA块完成中断

7. DMA初始化检查清单

   - DMA模块时钟和硬复位。
   - DMA触发源选择，例如ADCAINT2、ADCBINT2。
   - 源起始地址。
   - 目标起始地址。
   - 数据宽度，通常为16位ADC结果。
   - BURST_SIZE。
   - SRC_BURST_STEP、DST_BURST_STEP。
   - TRANSFER_SIZE。
   - SRC_TRANSFER_STEP、DST_TRANSFER_STEP。
   - WRAP设置。
   - 连续模式或单次模式。
   - DMA中断模式和PIE向量。
   - 清除残留触发标志和错误标志。
   - 最后启动DMA通道。


七、分散在多个ADC模块时的DMA管理
--------------------------------

F28377S普通DMA通道的源地址按步进规则变化，不能在一个burst中直接读取：

   ADCARESULT0、ADCBRESULT0、ADCCRESULT0、ADCDRESULT0

因为这些寄存器分属于不同地址区域，并不是一个连续数组。

推荐方案：

1. 高速控制量由CPU控制ISR直接读取

   gridVoltageRaw = AdcaResultRegs.ADCRESULT0;
   gridCurrentRaw = AdcdResultRegs.ADCRESULT0;

2. 不同ADC模块上的监测量使用不同DMA通道

   DMA CH2：ADCBRESULT0 -> PV_VoltageBuffer[]
   DMA CH3：ADCCRESULT0 -> PV_CurrentBuffer[]

3. 两个DMA块都完成后，后台任务按相同采样索引组合数据。

4. 不要让上层算法直接处理多个硬件数组。
   采集层应将它们组装为ADC_RawFrame或ADC_RealFrame。

5. 如果两个DMA通道必须保持严格对应，应增加：

   - blockReady标志。
   - blockSequence序号。
   - completedCount计数。
   - 必要时增加丢块/不同步检测。


八、DMA缓冲区管理
----------------

1. 单缓冲区

   优点：简单、占用RAM少。

   风险：CPU处理上一块数据时，DMA可能已经开始覆盖同一个缓冲区。

   适用条件：
   - CPU能在下一个块开始覆盖前完成处理。
   - 允许只读取最近一块数据。
   - 已明确处理任务和DMA块周期的关系。

2. 双缓冲区/Ping-Pong

   DMA写Buffer A时，CPU处理Buffer B。
   DMA写Buffer B时，CPU处理Buffer A。

   优点：
   - DMA写入和CPU计算互不覆盖。
   - 适合AVG、RMS、功率和波形记录。

   需要管理：
   - 当前DMA写缓冲区。
   - 当前CPU读缓冲区。
   - ready标志或队列。
   - 未及时处理时的overrun计数。

3. DMA ISR职责

   推荐只做：
   - 标记哪个块已经完成。
   - 切换缓冲区或记录完成序号。
   - 清除DMA标志。
   - PIEACK。

   不推荐在DMA ISR中做大量浮点、平方根、通信或长循环计算。

4. 后台任务职责

   Task_Measure等任务负责：
   - 原始码换算。
   - AVG、RMS、ripple RMS。
   - 最大值、最小值。
   - 功率计算。
   - 合法性检查。

5. 周期匹配示例

   采样率为20kHz，DMA每160个burst完成一块：

   blockPeriod = 160 / 20000 = 8ms
   blockRate = 125Hz

   如果Task_Measure每20ms才执行一次，单缓冲区可能在任务处理前被DMA覆盖多次。

   可选解决方法：
   - 使用Ping-Pong缓冲区。
   - 提高Task_Measure执行频率。
   - 增大DMA块长度。
   - 允许只使用最新块，但必须承认中间块会丢失。


九、AVG、RMS、纹波和功率
----------------------

1. 平均值

   average = sum(x[n]) / N

   适合：
   - PV电压。
   - PV电流。
   - 母线电压。
   - 温度。

2. 真有效值

   rms = sqrt(sum(x[n] * x[n]) / N)

   适合：
   - 电网交流电压。
   - 电网交流电流。

3. 直流纹波有效值

   rippleRms = sqrt(sum((x[n] - average)^2) / N)

   对PV电压、PV电流、母线电压而言，普通RMS通常与平均值接近。
   直流平均值加纹波RMS更有实际意义。

4. 有功功率

   activePower = sum(v[n] * i[n]) / N

   电压和电流必须来自时间对齐的采样点。

5. 交流整周期窗口

   20kHz采样、50Hz电网：

   samplesPerCycle = 20000 / 50 = 400

   使用400点、800点等整数周期窗口，可以减少非整周期截断造成的RMS误差。

6. 溢出与精度

   对Uint16原始码进行平方和时，必须确认累加变量位宽足够。
   不要默认Uint32一定能容纳任意窗口长度的平方和。
   可以使用更宽累加器、分段累加或先换算为float。


十、建议的软件职责划分
--------------------

adc.c
   - ADC模块上电和模式配置。
   - SOC与物理通道的映射。
   - 触发源和采样窗口配置。
   - ADC中断源选择。
   - 快速控制ISR入口。

dma.c
   - DMA通道与ADCINT触发源映射。
   - DMA源地址和目标缓冲区。
   - burst、transfer、step、wrap配置。
   - DMA块完成ISR。

variable.c / variable.h
   - 全局原始数据、真实值、AVG、RMS结构。
   - ready标志、块计数、错误计数。

task_measure.c
   - 数据块换算和统计处理。
   - AVG、RMS、ripple RMS、功率。
   - 多DMA数据块组合和同步检查。

PLL/电流环
   - 只使用高速瞬时值。
   - 不访问DMA管理细节。

MPPT
   - 主要使用PV电压和PV电流的平均真实值。

通信任务
   - 读取已经处理好的测量结构。
   - 不直接扫描DMA正在写入的缓冲区。


十一、快速保护与DMA的边界
------------------------

DMA块处理不能承担最快速的过流关断。

推荐保护层级：

1. 硬件最快保护

   CMPSS/外部比较器 -> ePWM Trip Zone -> 立即关闭PWM

2. 快速软件保护

   ADC控制ISR检查瞬时电流、电压和状态。

3. 中慢速软件保护

   DMA块统计检查过温、长期过压、传感器异常和趋势。


十二、命名建议
--------------

1. 名称必须包含业务含义，不使用sample、value、buffer等孤立名称。

   推荐：
   gridVoltageRaw
   inductorCurrentRaw
   pvVoltageAverageV
   pvCurrentAverageA
   dcBusRippleRmsV

2. 硬件层名称可以包含ADC模块和SOC信息。

   ADCB_PV_DMA_Buffer
   ADCA_ControlFrame

3. 业务层名称不要包含ADCA、SOC0、RESULT1等硬件信息。

4. 数组长度区分Word、Burst、Frame、Block。

   ADC_PV_DMA_BURST_COUNT
   ADC_PV_DMA_FRAME_COUNT
   ADC_PV_DMA_BUFFER_WORDS

5. 对“数量减一”的寄存器设置必须写注释。

   TRANSFER_SIZE = 159; // 160 bursts


十三、未来实施顺序
----------------

第1步：列出完整信号表

   信号名称、物理ADC引脚、量程、传感器比例、是否需要同步、处理速度等级。

第2步：按同步需求分配ADC模块

   对相位同步敏感的信号尽量放到不同ADC模块并行采样。
   适合批量监测的信号尽量放在同一模块并安排连续SOC。

第3步：建立SOC映射表

   明确每个物理通道对应哪个SOC、RESULT、触发源和ACQPS。

第4步：建立语义化数据结构

   Raw、instantaneous、average、rms、rippleRms。

第5步：确定快、中、慢处理路径

   哪些进入控制ISR，哪些由DMA成块采集，哪些由慢速任务处理。

第6步：设计DMA缓冲区和块周期

   计算burst数量、块周期、RAM占用和Task_Measure周期。

第7步：决定单缓冲还是Ping-Pong

   只要CPU处理时间可能与DMA写入重叠，就优先使用Ping-Pong。

第8步：加入块序号和错误计数

   检测DMA溢出、数据未及时处理、多通道不同步和丢块。

第9步：先验证原始码

   用固定输入检查SOC映射、RESULT顺序和DMA数组布局。

第10步：再加入真实值、AVG、RMS和业务算法

   每增加一层都单独验证，避免同时排查硬件映射和算法问题。


十四、常见错误提醒
------------------

1. 把物理通道编号误认为结果寄存器编号。

2. 认为同一个ADC模块内的多个SOC会真正同时采样。

3. 让一个DMA通道跨多个不连续ADC模块直接搬运。

4. 忘记BURST_SIZE和TRANSFER_SIZE通常填写“数量减一”。

5. SRC_TRANSFER_STEP和DST_TRANSFER_STEP配置错误，导致第二个burst开始地址错误。

6. DMA连续覆盖缓冲区时，CPU仍在读取同一个缓冲区。

7. DMA块周期短于后台任务周期，却没有Ping-Pong或丢块策略。

8. 在DMA ISR中进行长循环、平方根或通信。

9. 用非整周期窗口计算电网RMS，却没有考虑频率变化和窗口泄漏。

10. 对直流量只计算普通RMS，而没有计算平均值和纹波RMS。

11. 上层算法直接访问AdcaResultRegs，导致更换引脚或MCU时大量修改。

12. 只验证编译通过，没有在硬件上验证结果顺序、同步和DMA覆盖问题。


十五、一页式快速回忆
--------------------

1. CHSEL决定采谁，SOC决定任务和RESULT，TRIGSEL决定何时采。

2. SOC可以把不连续物理通道整理成连续RESULT，方便DMA。

3. 同一ADC模块内部顺序转换，不同ADC模块可以同步并行转换。

4. 一个普通DMA通道适合搬一个ADC模块内连续RESULT；跨模块通常分DMA通道。

5. 快速控制量进ADC控制ISR；监测量由DMA成块采集；慢速量后台处理。

6. DMA ISR只标记完成、切换缓冲区和清标志，复杂计算放Task_Measure。

7. Raw保存ADC码，instantaneous保存真实瞬时值，average/rms/rippleRms保存统计值。

8. 20kHz、50Hz电网一周期400点；160个burst对应8ms和125Hz块更新率。

9. DMA块周期必须与CPU任务周期匹配；有覆盖风险就用Ping-Pong。

10. PLL和电流环不应知道ADC引脚；MPPT和通信不应知道DMA寄存器。

11. 硬件快速过流使用CMPSS/Trip Zone，不能等待DMA块完成。

12. 未来移植时只替换BSP采集层，尽量保持上层语义数据结构不变。
