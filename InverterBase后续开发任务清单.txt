InverterBase 后续开发任务清单

说明
----
本文根据当前 InverterBase 工程的源码状态整理后续开发任务。
任务顺序按模块之间的依赖关系排列，具体控制算法需要结合实际逆变器拓扑、传感器量程、
硬件连接和并网规范确定。
本文不修改工程源码，不包含编译和硬件调试操作。


一、先固定系统接口和硬件定义
----------------------------

在继续编写控制算法前，先整理硬件参数表，至少包括：

1. ADC 通道与实际信号的对应关系。
2. 每个传感器的零点、增益和方向。
3. 电网电压、电感电流、母线电压、PV 电压和 PV 电流的实际量程。
4. PWM 输出对应的功率器件。
5. PWM 频率、死区和采样触发点。
6. 保护输入和 Trip-Zone 输入。
7. 电网继电器、预充电、风扇等 GPIO。
8. 电流和电压的正负方向定义。
9. 各运行状态的进入和退出条件。

主要文件：
   InverterBase/z6_bsp/adc.c
   InverterBase/z6_bsp/epwm.c
   InverterBase/z6_bsp/gpio.c
   InverterBase/z7_data/constant.h
   InverterBase/z7_data/variable.h

这一步的结果应是一份明确的信号、单位、方向和状态定义表。


二、完成测量链路确认
--------------------

Task_Measure() 已经包含 DMA 数据处理、平均值、平方均值、RMS、物理量转换和校准参数读取。
下一步需要逐项确认：

1. ADC 通道映射是否与硬件一致。
2. 各通道 offset 和 gain 是否与传感器量程一致。
3. 电流和电压的符号方向。
4. 各信号是否适合使用当前 RMS 算法。
5. 温度换算曲线和 NTC 参数。
6. 测量值上下限和无效状态的表示方式。
7. 采样块丢失、DMA 溢出或数据未更新的状态。
8. 通过 SCI 读取实际值，并与外部测量设备对照。

主要文件：
   InverterBase/z5_task/task_measure.c
   InverterBase/z6_bsp/dma.c
   InverterBase/z6_bsp/adc.c
   InverterBase/z7_data/variable.h
   InverterBase/z7_data/constant.h

控制算法使用的 gMachineData.realAvg 和 gMachineData.realRms 需要明确单位、方向和更新时间。


三、完成状态机
--------------

当前 InverterBase/z5_task/task_state.c 只有空框架。
可以根据设备实际运行流程定义类似以下状态：

   INIT
   SELF_CHECK
   WAIT_GRID
   PLL_LOCKING
   PRECHARGE
   READY
   RUN
   STOPPING
   FAULT
   FAULT_LATCHED

每个状态需要明确：

1. 进入条件。
2. 保持条件。
3. 退出条件。
4. PWM 是否允许输出。
5. 哪些控制环允许执行。
6. 发生故障后的处理。
7. 是否需要人工清除故障。

状态机需要统一使用：

   gSysFault
   PWM 使能和关闭接口
   继电器或接触器控制
   通信状态
   UI 显示状态

主要文件：
   InverterBase/z5_task/task_state.c
   InverterBase/z7_data/variable.h
   InverterBase/z6_bsp/epwm.c
   InverterBase/z6_bsp/gpio.c


四、完成电网检测和同步
----------------------

当前 InverterBase/z5_task/task_grid.c 是空框架。
z6_bsp/adc.c 中已经包含 PLL 运行和 PLL 锁定判断的基础。

Task_Grid() 可以继续完成：

1. 电网电压有效值判断。
2. 电网频率范围判断。
3. PLL 锁定和失锁状态管理。
4. 电网相位有效性判断。
5. 电网过压、欠压判断。
6. 电网过频、欠频判断。
7. 电网恢复确认时间。
8. 电网异常后的 PWM 关闭或状态切换。
9. 并网前等待条件。

需要先确定最终使用 SRF_PLL_Run() 还是 SOGI_PLL_Run()。
当前 main.c 使用 SOGI_PLL_Init()，并在 ADCA 快速中断中调用 SOGI_PLL_Run()。

主要文件：
   InverterBase/z5_task/task_grid.c
   InverterBase/z3_system/system.c
   InverterBase/z6_bsp/adc.c
   InverterBase/z6_bsp/ecap.c
   InverterBase/z7_data/variable.h


五、完成电流环和 PWM 控制
------------------------

当前 z6_bsp/adc.c 的 ADCA1_CPU_ISR() 中仍使用开环参考：

   InductorCurrentRef_temporal = InductorCurrentAmp_temporal * GridSPLL.sine;
   EPWM_SetDuty(0.5f * (1.0f + InductorCurrentRef_temporal));

下一步需要明确并实现实际的快速控制路径：

1. 选择电流控制结构，例如 PR、DQ 电流环或其他结构。
2. 使用实际电感电流反馈，而不是固定幅值。
3. 生成电流参考。
4. 计算电流误差。
5. 增加 PI 或 PR 控制器状态。
6. 处理控制器输出限幅。
7. 处理积分饱和。
8. 在 PLL 未锁定或状态不允许时禁止控制输出。
9. 规定 PWM 启动、停止和故障时的占空比。
10. 明确 ADC 采样时刻与 PWM 更新时刻的关系。

主要文件：
   InverterBase/z6_bsp/adc.c
   InverterBase/z6_bsp/epwm.c
   InverterBase/z5_task/task_grid.c
   InverterBase/z5_task/task_state.c
   InverterBase/z7_data/variable.h

快速控制变量和慢速任务变量需要定义各自的访问边界。


六、完成功率计算和功率限制
--------------------------

当前 InverterBase/z5_task/task_power.c 主要是 LED 心跳代码。
可以在 50 ms 任务中实现：

1. 电网有功功率计算。
2. 直流侧功率计算。
3. 输出功率平均值。
4. 功率方向判断。
5. 额定功率限制。
6. 母线电压限制。
7. 温度降额。
8. 电流限幅。
9. 功率变化斜率限制。
10. 将功率和限幅值发布给通信、UI 和控制环。

数据流程可以按以下形式组织：

   测量数据
       -> 功率计算
       -> 限幅和降额
       -> 电流参考幅值
       -> 快速电流环

主要文件：
   InverterBase/z5_task/task_power.c
   InverterBase/z7_data/variable.h
   InverterBase/z7_data/constant.h


七、完成 Boost 和 MPPT
----------------------

当前 InverterBase/z5_task/task_mppt.c 主要是 LED 心跳代码。

MPPT 慢速任务（100 ms）可以实现：

1. 读取 PV 电压和电流。
2. 计算 PV 功率。
3. 更新工作点。
4. 生成 PV 电压或功率参考。
5. 判断启动、停止和扫描条件。

如果硬件包含独立 Boost 功率级，还需要增加：

1. Boost 电感电流采样。
2. Boost PWM 配置。
3. Boost 电流环。
4. Boost 电压环。
5. 占空比限幅。
6. 母线过压保护。
7. Boost 过流保护。
8. Boost 启停顺序。

当前 EPWM_Config() 主要配置 EPWM3，需要确认 Boost 是否使用其他 ePWM 模块，
以及对应 ADC 采样是否已经配置。


八、集中实现保护逻辑
--------------------

当前 SysFault 主要包含：

   pllFault
   tzFault

后续可以根据实际保护需求扩展故障模型，例如：

   ADC_DATA_INVALID
   GRID_OVERVOLTAGE
   GRID_UNDERVOLTAGE
   GRID_OVERFREQUENCY
   GRID_UNDERFREQUENCY
   PLL_UNLOCK
   DC_BUS_OVERVOLTAGE
   DC_BUS_UNDERVOLTAGE
   INDUCTOR_OVERCURRENT
   GFCI_FAULT
   DCI_FAULT
   PV_ISOLATION_FAULT
   INVERTER_OVERTEMPERATURE
   BOOST_OVERTEMPERATURE
   COMMUNICATION_TIMEOUT
   EEPROM_ERROR
   PWM_TRIP

每个故障需要定义：

1. 是否立即关闭 PWM。
2. 是否只限制功率。
3. 是否允许自动恢复。
4. 是否需要人工清除。
5. 是否保存到 EEPROM。
6. 是否通过 SCI 和 OLED 显示。

保护逻辑可以按以下三部分分布：

   快速保护：ADC ISR、PWM Trip-Zone、硬件比较器
   周期保护：Task_State()、Task_Grid()、Task_Power()
   故障管理：记录、锁存、清除、通信发布


九、整理通信和 UI
------------------

task_comm.c 已经包含 SCI 帧解析和 CRC16。
后续可以增加：

1. 返回真实物理量，而不是只返回原始 ADC 值。
2. 返回完整运行状态和故障位。
3. 增加校准参数读取和写入命令。
4. 增加启动、停止和故障清除命令。
5. 增加参数范围检查。
6. 增加通信超时检测。
7. 增加固件版本和硬件版本。
8. 定义协议版本号。

同时需要确认 pc_tools/inverter_serial.py 与目标板的协议字段一致。

UI 可以显示：

   电网电压、电流、频率
   PV 电压、电流、功率
   母线电压
   输出功率
   PLL 状态
   当前运行状态
   当前故障


十、完善 EEPROM 参数管理
------------------------

EEPROM 基础读写框架已经存在，后续可以定义：

1. 出厂默认校准值。
2. 参数缺失时的默认处理。
3. CRC 错误处理。
4. 版本变化后的迁移方式。
5. 校准参数写入触发条件。
6. 写入失败的故障表现。
7. 参数写入次数限制。
8. 用户参数和校准参数是否分开存储。
9. 是否需要双备份记录。

主要文件：
   InverterBase/z5_task/task_e2prom.c
   InverterBase/z6_bsp/i2c.c
   InverterBase/z7_data/variable.h


十一、建议的实际开发顺序
------------------------

1. 固定硬件信号、单位、方向和保护阈值。
2. 完成 ADC/DMA 测量链路确认。
3. 完成 SCI 测量监视和调试数据输出。
4. 完成故障数据结构。
5. 完成 Task_State()。
6. 完成 Task_Grid()。
7. 完成 PLL 锁定后的并网条件。
8. 用实际电流反馈替换当前开环 PWM。
9. 完成 Task_Power()。
10. 完成 Boost 和 MPPT。
11. 完成快速保护与慢速保护。
12. 完成通信命令、UI 和 EEPROM 参数管理。
13. 进行分阶段联调。

依赖关系可以概括为：

   ADC/DMA 测量确认
       -> 状态机
       -> 电网同步
       -> 电流环
       -> 功率管理
       -> MPPT/Boost
       -> 保护和联调

当前从工程结构看，最先需要处理的是测量链路和状态机；MPPT 依赖 PV 测量、功率计算、
功率限制、状态机以及 Boost 控制接口。
